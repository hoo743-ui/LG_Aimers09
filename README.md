# LG Aimers 9기 Phase 2 — 투구 제구 성공 확률 예측

투구 직전까지 확인 가능한 정보만으로 각 투구의 **제구 성공 확률**을 예측한다.
평가지표는 **Brier Skill Score** — 확률의 순위가 아니라 확률값 자체의 정확도를 잰다.

```
Score = max(0, 100000 × (1 − Brier / r(1−r)))      r = 해당 평가셋의 실제 성공률
```

즉 **Score ≈ BSS × 100,000**. Brier 를 기준선 대비 1% 줄이면 1000점이다.

### 로컬 ↔ LB 환산

**보정 있는 점과 없는 점을 한 직선에 섞으면 안 된다.** 예전에 세 점(1·3·4회차)

822.57** 이었다 — 잔차 −12.3 으로 기존 잔차(±5.3)를 넘는다. 1회차는 보정 없음,
3·4회차는 보정 있음이었고, 보정은 평가셋에서 로컬보다 크게 먹혔다.

두 무리를 나눠서 맞춘다. 규칙 준수 대응점은 넷이다.

| 회차 | 로컬 | LB |
|---|---|---|
| 1 | 415.57 | 549.64 |
| 6 | 661.03 | 822.57 |
| 7 | 679.23 | **834.58** |
| 8 | 683.77 | **825.13** ← 로컬은 최고인데 LB 는 후퇴 |

**8회차가 이 관계를 함수가 아니게 만들었다.** 로컬이 가장 높은 구성이 LB 는
9점 낮다. 즉 **로컬 홀드아웃은 이 마진에서 더 이상 신뢰할 수 없다.**

```
증분 전달률   1→6회차  +245.46 → +272.93   1.112
              6→7회차   +18.20 →  +12.01   0.660
              7→8회차    +4.54 →   −9.45  −2.08   ← 부호가 뒤집힌다
```

절대 위치 추정에는 1·6·7 회차 세 점을 쓴다 (8회차는 벗어난 점이다).

```
LB ≈ 1.094 × 로컬 + 95.25
```

**1등이 1000 을 넘겼다 = 로컬 약 820 이 필요하다.** 지금 661 이니 **160점 차**다.
(예전에 적었던 106점은 위 혼합 직선에서 나온 값이라 과소평가였다.)

> **격차는 국면 보정으로 설명되지 않는다 — 이게 제일 중요하다.**
> 6회차에 보정을 얹었을 때 로컬이 714.20 이었으므로, 보정 있는 직선에 넣으면
> 약 **881** 이다. 즉 보정의 값은 +59 정도이고,
>
> ```
> 822.57   현재 (규칙 준수)
> 881.5    보정을 얹었다면 (위반)     ← 보정 = +59
> 1000+    1등
> ```
>
> **우리 자신에게 위반을 허용해줘도 120점이 남는다.** 1등이 높은 건 평가셋 보정
> 때문이 아니다. 로컬 환산 약 108점어치의 실력이 우리에게 없는 것이다.
> 규칙 해석 문제가 아니라 모델링 문제로 봐야 한다.

두 점짜리 직선이라 자유도가 0 이고, 1회차는 모델 계열부터 다른 RandomForest 라
외삽이 불안하다. 다만 **채점이 같은 평가셋에서 이뤄지므로 제출 간 비교는 정밀
하다** — 6회차(822.57)를 앞으로의 규칙 준수 기준점으로 쓰면 된다.

> **작은 개선은 이 직선으로 예측되지 않는다.** 4회차에서 로컬 +16.97 을 얻고
> LB +9.40 을 받았다 — 환산 0.55 로 직선 기울기(1.16)의 절반이다. 잔차가 ±5 이니
> 로컬 20점 미만의 차이는 LB 에서 확인될지 장담할 수 없다.
>
> 원인은 폴드 의존성이다. ID 복원 효과가 2021 −9.6 / 2022 +13.5 / 2024 +21.6 로
> 해마다 크게 달랐는데, 2024 값에 무게를 두고 예측했더니 평가 시즌은 그보다
> 작았다. **폴드별로 부호나 크기가 흔들리는 개선은 그 변동폭만큼 할인해서 볼 것.**
>
> 채점은 같은 평가셋에서 이뤄지므로 제출 간 비교 자체는 정밀하다. +9.40 은 측정
> 노이즈가 아니라 실제 개선이다.

> 요구하는데 현재 작업 PC 는 3.10 뿐이다. 중요한 건 절대 버전이 아니라
> **pkl 을 만든 sklearn 버전과 `requirements.txt` 핀이 같은 것**이므로, 양쪽을

## 4. 알아낸 것

### 4-1. 이 문제는 "표현력"이 아니라 "과신하지 않기" 싸움이다

| 모델 | 2024 검증 |
|---|---|
| RandomForest `max_depth=10` (베이스라인) | 415.57 |
| HGB 조기종료 (`validation_fraction=0.1`) | **379.01** |
| HGB 256회 (곡선에서 최적점 선택) | 627.05 |
| HGB L10 `min_leaf=1000` 1000회 | **640.01** |

sklearn 의 조기종료는 **학습 데이터 안에서 무작위로** 10% 를 떼기 때문에 같은
시즌끼리 비교하게 되고, 시즌이 바뀔 때의 일반화 실패를 감지하지 못한다. 그래서
수백 회를 더 돌아 과신 상태로 갔다(예측 범위가 0.28~0.72 까지 벌어짐).

**반드시 시즌 단위 홀드아웃으로 반복수를 정할 것.** `staged_predict_proba` 를 쓰면
학습 한 번으로 전체 곡선이 나온다 (`diag_curve.py`).

잎 개수 봉우리는 L10 근처다. 잎이 적을수록 반복수는 늘어난다.

```
L4 587.99   L7 608.12   L10 640.01 ★   L15 632.38   L31 627.74   L63 602.29
```

### 4-2. 타깃 비율이 해마다 떨어진다 — 가장 중요한 구조적 사실

| 시즌 | 실제 성공률 | 누적 `asof_pitcher_success_rate` | `asof_..._prev1_game` |
|---|---|---|---|
| 2019 | 0.5647 | 0.5598 | 0.5613 |
| 2020 | 0.5327 | 0.5472 | 0.5340 |
| 2021 | 0.5328 | 0.5355 | 0.5291 |
| 2022 | 0.5289 | 0.5354 | 0.5268 |
| 2023 | 0.5000 | 0.5237 (**−0.024**) | 0.5044 (−0.004) |
| 2024 | 0.4861 | 0.5114 (**−0.025**) | 0.4884 (−0.002) |

**누적형 `asof` 는 경력 전체 평균이라 하락을 뒤늦게 따라간다.** 최근 2년은 0.025 나
뒤처진다. 반면 `prev1_game` 계열은 현재 국면을 거의 정확히 반영한다.

중심이 `d` 만큼 어긋나면 `d²/r(1−r)×100000` 점을 잃는다. 2024 폴드의 편차 0.0119 는
57점이다. 연도별 난이도가 극단적으로 갈리는 이유다.

```
2021 → 1192.84     2022 → 2249.51     2023 → 0.00     2024 → 639.04
```

> **2023 형 붕괴는 중심 보정으로 못 막는다.** 정답 성공률로 중심을 완벽히 맞춰도
> 2023 은 여전히 0.00 이다. 중심을 제거하고 남는 실력이 상수 예측보다 못하다는
> 뜻이다(BSS 음수 → `max(0,...)`). 국면이 바뀌면 중심만 어긋나는 게 아니라 피처와
> 타깃의 관계 자체가 끊어질 수 있고, 그때는 어떤 사후 보정도 소용없다.

### 4-3. 국면 보정 🚫 규칙 위반 — 쓰지 말 것

평가셋 전체의 `prev1` 평균으로 예측 중심을 옮기는 방법이다. 2024 폴드에서 +54,
리더보드에서 549.64 → 862.75 를 만든 핵심이었다. **그리고 규칙 위반이다.**

```
data_description.md 5) 금지 예시
  - test.csv 내부 빈도값 또는 분포 통계
  - 평가 데이터 전체를 보고 만든 사후 보정값     ← 이것
```

판단이 어긋난 지점 — "평가셋의 **정답**을 안 보니 괜찮다"고 생각했다. 규칙이 금지하는
건 정답 참조가 아니라 **다른 행 참조**다. 3·4회차 제출(862.75, 872.15)이 이 상태이고,
보정을 뺀 실력은 로컬 645.54 / LB 약 817 이다.

`script.py` 에서 제거했다. 같은 이유로 `detrend`(평가셋 리그 평균 차감)도 제거했다.

**추정기 자체는 유효한 관측이다.** 다른 용도로 쓸 수 있으니 남긴다 — `prev1` 의
단면 평균은 그 시즌 성공률을 **평균 오차 +0.0002, 표준편차 0.0031** 로 맞힌다.
누적형이 최근 두 해에 0.024 씩 밀리는 것과 대조적이다.

**합법 대체 수단은 찾지 못했다.** 시도와 결과는 4-5 에 있다.

### 4-4. Trackman 연결 — 성공했지만 점수는 안 올랐다

기존 결론("ID 체계가 달라 조인 불가")은 **틀렸다.** ID 직접 비교만 확인하고 접었던
것이 오판이다. 경기를 맞추면 대응표를 역산할 수 있다.

`trackman_link.py` 의 부트스트랩 3단계:

1. `(시즌, 월, 요일, 투구수)` 가 양쪽에서 유일한 경기부터 맞춘다 (42.3%)
2. 그 매칭에서 **팀 코드 ↔ 팀 id 를 다수결로 역산** — 알고리즘은 팀 이름을 모른다
3. 팀 대응표로 나머지를 확정 (64.9%), 경기 안에서 투수를 등판 순서·투구 수로 짝짓는다

```
팀 13개 — KBO 10구단 + KBO_POL, KBO_ARM, MIN_HAW  (train 의 팀 id 개수와 일치)
투수 592명 / 792명, 신뢰도 90% 이상 전원, 중앙값 100%, 중복 배정 0
→ pitcher_id_map.csv
```

팀 이름을 모르는 상태에서 KBO 10구단이 정확히 복원된 것이 매칭이 옳다는 증거다.
요일 규약(월=0)은 경기 수 대조로 확정했다.

**그런데 물리 프로필 피처는 실패했다** (3폴드, base 대비): 전체 26개 **−17.17**,
릴리스 반복성 4개만 **−5.95**. 커버리지는 충분했다(학습 97.6% / 검증 79.0% —
검증 상한은 매칭이 아니라 선수 유입률이 정한다. 2024 는 투구의 19.9% 가 신인).

**왜 실패했나.** `pitcher_id` 가 이미 투수를 식별한다. 프로필은 투수당 값 하나인
**정적 상수**라, 트리 입장에서 이미 아는 대상을 다른 좌표계로 다시 말하는 것에
가깝다. ID 복원이 +8.5 였던 것의 뒷면이다. 게다가 2025 예측에 쓸 수 있는 trackman 은
2024 가 최신이라 "지금의 반복성"을 말할 수 없다.

**재조사 결과 — trackman 은 죽었다. 이번엔 근거가 확실하다** (`probe_trackman.py`).

원래 판정은 "정적 프로필이 `pitcher_id` 와 중복"이었는데, `pitcher_id` 가 데뷔 순
프록시일 뿐이라는 게 밝혀져(4-7) 그 논거가 약해졌다. 그래서 **실제 모델 잔차를
기준선으로** 다시 쟀다 — "이 정보에 신호가 있나"가 아니라 "**모델이 이미 아나**".

| 후보 | 상한 (자기 정답 봄) | 이식 이득 | 계수 부호 |
|---|---|---|---|
| `career_bb` *(모델에 이미 있음, 검증용)* | 2.65 | −0.94 | — |
| `bb_by_count` (투수 x 카운트 구종 분포) | **8.75** | −6.47 | + / + / − |
| `relh_std` (릴리스 높이 산포 = 반복성) | 2.84 | −1.88 | − / + / − |
| `rels_std` (릴리스 좌우 산포) | 3.14 | −3.96 | + / + / − |
| `fb_by_count` | 7.76 | +2.76 | + / − / − |
| `velo_by_count` | 0.99 | +0.06 | — |
| `relh_career` | 1.67 | +0.14 | — |

**상한이 전부 한 자릿수다.** 계수를 그 폴드 정답으로 최적화해도 최대 8.75 점이고,
이식하면 음수거나 0 이다. 모든 후보에서 **계수 부호가 폴드마다 뒤집힌다** —
노이즈의 서명이다.

원래 판정보다 강한 이유가 셋이다.
1. 기준선이 실제 모델 예측이라 "이미 아는 정보"가 자동으로 걸러진다
2. 4-4 가 안 해본 **조건부** 형태(투수 x 카운트 구종 분포)를 포함했다
3. 4-4 가 "제구의 물리적 실체"로 지목한 **릴리스 반복성**을 표준편차로 제대로
   넣었다. 그것도 죽었다

자체 검증이 통과했다 — 모델에 이미 있는 `career_bb` 가 −0.94 로 0 근처다.

> **미검증으로 남은 것은 투구 단위 매칭뿐이다.** train 행과 trackman 투구를
> 1:1 로 맞추면 구종별 제구 능력(“이 투수는 슬라이더 제구가 나쁘다”)을 만들 수
> 있다. 다만 구종 **분포** 자체가 자기 정답을 봐도 8.75 점인 이상 그 하위 경로의
> 기대값도 낮고, 정렬 비용은 훨씬 크다.
>
> **`trackman` 관련 컬럼은 `pitcher_hand`/`batter_hand` 코드 체계가 train 과 다르다**
> (trackman `'Left'/'Right'` vs train `int {1,2}`). 조인하면 조용히 전부 결측이
> 되므로 커버리지를 반드시 확인할 것.

남길 것** (같이 빼면 −20.45).

> 고갈됐다"는 결론은 그 범위 안에서만 맞다. 조건부·상호작용 축은 열어본 적이

### 4-7. 탐욕적 부스팅의 사각지대 — 주변부가 0 인 상호작용

**`same_hand` 컬럼 하나로 +24.66** (3폴드 x 2시드, 폴드 부호 전부 일치). 4-5
기각 목록의 어떤 항목보다 크고, 유일한 합법 채택이었던 `pitcher_id` 복원(+8.5)의
세 배다. 그리고 새 데이터를 하나도 안 쓴다 — 이미 있던 두 컬럼의 함수다.

```python
same_hand = (pitcher_hand == batter_hand)
```

**왜 4년간 못 찾았나.** 동일 손 매치업은 투수에게 유리하다. 그런데 그 효과는
어느 한쪽만 봐서는 보이지 않는다.

```
        좌타   우타
  좌완    +      -
  우완    -      +
```

`pitcher_hand` 의 주변부 평균도, `batter_hand` 의 주변부 평균도 상쇄돼 0 이다.
탐욕적 트리는 루트에서 **주변부 이득**으로 분할을 고르므로 두 컬럼 중 어느 쪽도
선택하지 않는다. 트리를 1100 그루 돌려도 마찬가지다 — 파라미터가 아니라
**알고리즘의 구조적 사각지대**다. 두 컬럼은 4년 내내 47개 피처 안에 있었다.

**인코딩 형태가 크기를 바꾼다.**

| 형태 | 3폴드x2시드 | 폴드 부호 |
|---|---|---|
| `same_hand` = (같은가) 이진 | **+24.66** | 일치 |
| `hand_mix` = `pitcher_hand*2 + batter_hand` 4수준 | +19.09 | **2024 −3.48 엇갈림** |

4수준 순서 코드는 동일 손 `{3,6}` 이 인접하지 않아 한 번의 분할로 못 가른다.
**메커니즘을 그대로 인코딩할 것.** 교차곱을 기계적으로 만들지 말고, 무엇이
신호인지 정하고 그것만 이진으로 준다.

> **`pd.factorize` 를 제출 경로에 쓰지 말 것.** 등장 순서로 코드를 매기므로
> train 과 test 에서 값이 갈리고, 모델이 조용히 망가진다. `pitcher_hand` /
> `batter_hand` 는 `int64 {1,2}` 라 산술로 결정적이다.

**같은 원리로 나머지를 훑었고 전부 죽었다.** 주변부 효과가 강한 쌍은 트리가
루트에서 이미 고르므로 상호작용도 이미 잡고 있다. 사각지대는 주변부가 0 인
자리에만 생긴다.

| `mix_count` (좌우 x 카운트) | +23.70 | `same_hand` 재발견. 카운트 차원은 0 |

HGB 가 이미 잡고 있는 것까지 "발견"으로 올렸다.

**자체 검증이 통과한다.** 캐시된 예측은 `same_hand` 가 들어간 모델의 것이므로

새 기준선에서 **최대가 +8.05** 이고, 그 1위(`balls x strikes`)는 이미 `count_state`
로 실제 학습에서 시험해 **−6.28** 이었다. 상한이 한 자리인 후보가 학습에서
살아남을 가능성은 낮다. 2차 조합은 여기서 닫는다.

> **더 중요한 것은 `main` 열이 전부 음수라는 사실이다** (−18 ~ −176). 이력 시즌의
> 셀 평균을 평가 시즌에 옮기면 반드시 손해다. 원인은 중심 편차다 —
>
> ```
> 2024 잔차 평균 −0.01186   →   0.0119² / 0.24981 × 100000 = 56.7 점
> ```
>
> **지금 남은 손실 중 가장 큰 단일 항목이다.** 중심만 맞히면 로컬 661 → 718 이다.
> 규칙 위반이었던 국면 보정이 만든 +53.17 이 정확히 이 자리다 (4-3).
> 4-2 가 기록한 국면 이동이 상호작용 탐색에서 이런 형태로 다시 확인된 셈이고,
> **탐색 방향이 상호작용에서 "중심을 합법적으로 맞히는 법"으로 옮겨간다.**

### 4-8. 모델 계열 혼합 — 단독으로 지는 모델이 섞으면 이긴다

7장에 "로지스틱이나 RF 를 소량 섞기. 기대는 낮다"고 한 줄 적힌 채 4년간 측정된
적이 없었다. 재보니 **2024 폴드 +8.24** 다.

| | 단독 (3폴드) | 최적 혼합 | 폴드 부호 |
|---|---|---|---|
| `rf` (규제 강화) | **+1.47** | w=0.3 → +40.67 | 전 가중치 일치 |
| `logreg` | −245.22 | w=0.2 → +38.25 | w=0.3 에서 갈림 |
| `et` | −81.43 | w=0.1 → +15.54 | w≥0.2 에서 갈림 |

**RF 가 튜닝된 HGB 와 동등하다.** 1회차 베이스라인이 415.57 이었던 건 RF 가
나빠서가 아니라 `max_depth=10` 으로 규제가 없어 과신했기 때문이다.
`min_samples_leaf=2000` 으로 잡으면 대등하다.

**이득의 정체는 중심 보정이 아니라 오차 상쇄다.** 혼합 전후로 중심 편차가 거의
안 변한다(2024 +0.0121 → +0.0109). 그래서 2025 국면이 어느 쪽으로 움직여도
비교적 안전하다.

> **3폴드 평균(+30~47)을 그대로 믿으면 안 된다.** 이득이 학습 시즌이 적은 폴드에
> 몰려 있다. RF 단독 성적이 `2021 +128 → 2022 −39 → 2024 −92` 로 시즌이 쌓일수록
> 단조 감소하고, 2021 의 큰 이득은 `n_iter=1100` 이 2시즌짜리 폴드에 안 맞아
> HGB 가 과적합한 탓도 있다. **실제 2025 는 학습 6시즌으로 어느 폴드보다 많으므로
> 2024 폴드 값이 상한이다.**

**채택은 로지스틱 `w=0.10` 뿐이다. 🚫 RF 는 실전에서 해로웠다 — 켜지 말 것.**

8회차로 3자 혼합 `hgb .75 / rf .20 / lr .05` 를 제출했다. 3폴드 +17.43,
2024 폴드 +5.05, 부호 전부 일치, 홀드아웃 683.77 — 모든 지표가 양수였다.
**그런데 LB 가 834.58 → 825.13 으로 −9.45 였다.**

```
로컬 +4.54  →  LB −9.45      전달률 −2.08
```

**원인은 예측 가능했고, 실제로 적어두고도 무시했다.** RF 단독 성적이 학습 시즌
수에 따라 단조 감소한다.

```
RF − HGB :  2시즌 +128.3   3시즌 −38.8   5시즌 −92.1   →  6시즌은 더 나쁘다
```

실제 평가는 학습 **6시즌**으로 어느 폴드보다 많다. 2024 폴드가 양수라는 이유로
채택한 것이 판단 착오였다.

> **교훈 — 폴드 효과가 학습량과 함께 단조 변하는 변경은 2024 폴드조차 낙관적이다.**
> 4-6 은 "2024 에 무게를 두지 말라"고 경고했는데, 그 경고로도 부족하다.
> 2024 는 5시즌이고 실제는 6시즌이라 **여전히 한 칸 모자란 지점**이다.
> 추세가 단조면 6시즌으로 외삽해야 하고, 외삽이 불안정하면(4-11) **채택하지 말 것.**

> **작은 로컬 이득은 LB 로 옮겨지지 않는다.** 관측된 전달률이
> +18.20 → +12.01 (0.66) 과 +4.54 → **−9.45** (−2.08) 다. **로컬 +5 급 변경은
> 부호조차 보장되지 않는다.** 최소 +15~20 이상, 그리고 추세가 유리한 방향일 때만
> 제출 기회를 쓸 것.

참고로 배선 자체는 문제가 없었다 — pkl 2.95MB → 8.2MB, 추론 35.3초,
**RF 직렬화가 낮은 numpy(1.26.4)에서 정상 로드**됐다 (6-4 는 HGB 전용 문제다).
실패한 것은 배선이 아니라 선택이다.

### 4-9. 중심 보정 — 합법 경로를 찾았다

4-3 의 위반은 **평가셋 전체의 `prev1` 평균**을 계산한 것이었다. 그런데 각 행
**자신의** `asof_*` 는 운영이 제공한 공식 입력이고, `prev1` 은 그 투수의 직전
경기에서 계산되므로 **평가 시즌의 국면 수준을 담고 있다.**

```python
p' = p + lam * (그 행의 prev1 - c)      # lam, c 는 학습 시점 상수
```

행 독립이 유지된다. 4-3 과 다른 점은 하나 — 집계가 없다.

**4-5 의 기각("행 단위 기준선 잔차 학습" −23.8)은 왜 틀렸나.** 진단("기준선 표본이
작아 노이즈가 1:1 로 실린다")은 맞았지만 해법을 안 찾았다. 닫힌 해가 있다.

```
Brier 변화 = 2·lam·E[(A-c)(p-y)] + lam²·E[(A-c)²]
최대 이득  = E[(A-c)(p-y)]² / E[(A-c)²]      분모가 anchor 의 분산
```

**lam 을 LOO 로 자동 적합하면 실패한다** (prev5 평균 −1.06, 부호 엇갈림). cap 이
큰 폴드가 lam 을 끌어올려, 이미 중심이 맞은 폴드(2022, 편차 +0.0002)를 망친다.
**작게 고정해야 한다** — 이득 곡선이 `cap·(1−(1−lam/lam*)²)` 이라, 작게 잡으면
cap 이 큰 폴드에서 이득을 가져오면서 손실은 묶인다.

| anchor | 세 폴드 모두 양수인 lam | 3폴드 | 최악 | 2024 |
|---|---|---|---|---|
| **`prev1`** | **0.03** | **+13.84** | **+1.69** | **+7.81** |
| `prev135` | 0.02 | +10.22 | +0.34 | +9.04 |
| `cumul` | 0.01 | +2.37 | +0.00 | +2.99 |
| `prev3`·`prev5`·`prev35`·`batter_cumul` | 없음 | — | — | — |

**상한이 큰 anchor 가 아니라 `lam*` 이 균일한 anchor 를 골라야 한다.** `prev5` 는
cap 이 훨씬 크지만(100/0/30) `lam*` 이 0.201~−0.003 으로 흔들려 어떤 고정값도
2022 를 다치게 한다. `prev1` 은 노이즈가 커서 `lam*` 이 자동으로 0 쪽에 눌려
있고(0.090/0.018/0.033) 고정 0.03 이 세 폴드 모두에서 거의 최적이다.

**혼합(4-8)과 거의 독립이다** — 겹침 −0.1 ~ −3.4. 기전이 다르다(오차 상쇄 vs
수준 이동).

**더 밀어봤지만 전부 기각이다** (`center_test.py`, `alpha_test.py`).

| 시도 | 최선 | 왜 실패했나 |
|---|---|---|
| 차분 anchor `prev5 − cumul` | +6.47 | 표류를 직접 재지만 `prev1`(+13.86)을 못 이긴다 |
| 다변량 동시 적합 (축소 s) | +2.25 | 계수를 2폴드에서 적합하면 2022 가 무너진다 |
| **축소계수 `alpha` 고정** | **없음** | 2022 가 `a=1.01` 부터 −0.70. 세 폴드 양수 지점이 없다 |

> **같은 처방이 두 번째에는 안 통했다 — 조건이 있다.** 중심 보정을 살린 것은
> "LOO 로 맞추지 말고 작게 고정"이었다. `alpha` 에 그대로 적용했는데 실패했다.
> 차이는 **cap 이 작은 폴드의 손실 곡선 기울기**다. 중심 보정은 2022 의 cap 이
> 0.02 라 고정값을 써도 손실이 −0.5 수준이었지만, `alpha` 는 2022 가 처음부터
> 가파르다. **처방을 옮기기 전에 "손해 보는 폴드가 얼마나 빨리 나빠지는가"를
> 먼저 볼 것.**

중심 편차는 보정 후에도 **+0.0101** 남아 있고 이는 약 41점이다. 위 세 시도로
회수되지 않았다.

```
        기준      +혼합    +중심    +둘다
2021  1225.86    +52.55   +32.02   +81.17
2022  2261.04    +10.63    +1.69   +12.21
2024   660.95     +9.34    +7.81   +16.03
```

### 4-10. 손실 지도 — 남은 격차의 성격

기법을 더 시도하기 전에 **손실이 어디 있는지** 재야 한다 (`error_map.py`).

```
2024 분해:  불확실성 0.249807
            해상도    0.001797   (719.2 점)
            신뢰도오차 0.000157   ( 62.9 점)   <- 캘리브레이션 총량
```

**캘리브레이션 계열로 되찾을 수 있는 전부가 62.9 점이고 4-9 로 이미 8 을 썼다.**
구간별 격차(볼카운트 78.1, 팀 70.0, 월 65.8, 투수경험 60.2)는 전역 중심 편차를
다시 측정한 것일 뿐 독립적으로 되찾을 구조가 아니다 — 전부 전역값 62.9 근처다.
유일한 예외가 월별 표류(3월 +0.0084 → 9월 +0.0190)인데 전역 상수를 뺀 순수
기여는 약 8점이다.

**남은 격차는 전부 해상도다.** LB 1000 = BSS 0.0100 이면 신뢰도오차를 0 으로
만들어도 해상도가 **39% 더** 있어야 한다.

**자원 감사 — 모델 쪽에 회수할 낭비는 없다** (`feat_audit.py`).

| 가설 | 측정 | 판정 |
|---|---|---|
| 잎 10개 예산에 48개 피처는 낭비 | 이득 0.1% 미만 10개 제거 → **−3.91** | 반증 |
| `season` 은 추론 시 상수라 낭비 | 제거 → 2024 **660.95 → 210.59** | 반증 |

**`season` 은 이 모델에서 가장 중요한 장치다.** 판별이 아니라 **수준 보정**을
한다 — 평가 행을 "가장 최근 시대" 가지로 보내 국면에 적응시킨다. 덤으로 4-5 의
수수께끼가 풀린다. "최근 시즌만 학습"(−41~−95)과 "최근 가중"(−34~−57)이 실패하고
"전체 균등이 최선"이었던 이유는 **`season` 이 이미 그 일을 데이터 손실 없이
하고 있었기 때문**이다.

탐욕적 분할기는 쓸모없는 피처를 그냥 안 고를 뿐 있다고 손해 보지 않는다.
`asof_pitcher_pitchmix_n` 은 5개 모델 6,050 그루에서 **분할 0개**다.

### 4-11. 2023 형 붕괴의 정체 — 신호가 사라진 게 아니라 모양이 무너진 것

**2023 을 버린 것이 이 프로젝트 최대의 방법론적 실수였다.** 4-6 은 "어떤 구성
으로도 0점이라 비교에 정보가 없다"며 제외했는데, 0 으로 만든 것은 `max(0, ...)`
**클리핑**이지 폴드가 아니다. 클리핑 없는 BSS 로 재면 완벽히 비교 가능하다.
되살려 보니 폴드 하나가 결론을 뒤집는다.

`extrap_test.py` / `regime_diag.py` — 클리핑 없는 BSS x 100000, `L10` 기준:

| 폴드 | 실제 r | 중심편차 | BSS | 중심만 보정 | **완전 재보정** | 재보정 이득 |
|---|---|---|---|---|---|---|
| 2020 (1시즌) | .5327 | +.0308 | 51.8 | 432.9 | 668.7 | +616.9 |
| 2021 (2시즌) | .5328 | −.0087 | 1206.2 | 1236.4 | 1321.9 | +115.7 |
| 2022 (3시즌) | .5289 | +.0001 | 2260.0 | 2260.0 | 2214.2 | −45.8 |
| **2023 (4시즌)** | .5000 | +.0222 | **−1339.9** | −1143.4 | **490.6** | **+1830.5** |
| 2024 (5시즌) | .4861 | +.0118 | 660.1 | 715.7 | 716.5 | +56.5 |

**2023 의 순위 품질은 490.6 으로 2020(669)·2024(717)과 같은 자릿수다.** 모델의
순위 매기기는 그 해에도 멀쩡했다. 손실 1830 이 **전부 캘리브레이션**이고,
중심만 맞춰서는 196 밖에 못 되찾는다.

> **4-2 의 해석을 수정한다.** 4-2 는 "국면이 바뀌면 피처와 타깃의 관계 자체가
> 끊어진다"고 봤다. 실제로는 **관계는 살아 있고 확률의 모양(scale)이 무너진다.**
> 되찾을 수 없는 손실이 아니라 되찾는 법을 모르는 손실이다.

**이것이 축소계수 이식이 실패한 이유다.** 폴드마다 부호가 반대다.

- 2024 는 **과소확신** (최적 alpha 1.128, 벌려야 이득)
- 2023 은 **과대확신** (재보정이 1830 을 되찾는다 = 과하게 퍼져 있다)

| alpha | 1.00 | 0.95 | 0.90 | 0.85 | 0.80 |
|---|---|---|---|---|---|
| 2023 | −1339.9 | −1211.3 | −1092.4 | −983.3 | −884.0 |
| 2024 | 660.0 | 643.9 | 621.6 | 593.2 | 558.7 |
| **5폴드 평균** | 567.6 | 598.9 | 621.8 | 636.2 | **642.2** |

**5폴드 기준 최적은 alpha 0.80 이고, 2023 을 빼면 1.00 이다.** 폴드 하나가
답을 뒤집는다.

> **그래도 alpha 는 1.00 으로 유지한다.** 축소는 붕괴 해에 거는 보험인데
> (2023 +456) 정상 해에는 손해다 (2024 −101). 그리고 **2025 가 붕괴 해가
> 아니라는 직접 증거가 있다** — 붕괴 해였다면 우리 LB 가 0 근처였을 것이고
> 실제로는 822.57 / 834.58 이다. 여기서는 5폴드 평균이 잘못된 목적함수다.
> 평가 시즌의 유형을 이미 관측했기 때문이다.

**"완전 재보정 716.51" 은 제출할 수 있는 모델이 아니다.** 그 폴드의 **정답**으로
구간을 갈아끼운 상한이다. 2025 는 정답이 없으니 계산 자체가 불가능하다.

**그 모양 보정을 학습 시즌에서 배워 옮기는 것은 합법인데, 전혀 안 된다.**

| 평가 | 학습원 | 기준 | 등온 이식 | 차이 | (상한) |
|---|---|---|---|---|---|
| 2021 | 2020 | 1206.23 | 776.47 | **−429.76** | 1321.89 |
| 2022 | 2021 | 2260.02 | 1455.62 | **−804.40** | 2214.21 |
| 2023 | 2022 | −1339.95 | −1589.14 | **−249.19** | 490.59 |
| 2024 | 2023 | 660.05 | 534.76 | **−125.29** | 716.51 |

네 폴드 전부 크게 음수다. **캘리브레이션 축은 여기서 완전히 닫힌다.**
파라미터 수에 따라 이식 가능성이 깔끔하게 갈린다.

```
위치 (중심 이동, 1개)     이식됨            +7.16     채택 (4-9)
척도 (alpha, 1개)         부호 뒤집힘                  기각
모양 (등온 회귀, 20개+)    적극적으로 유해   −125~−804  기각
```

**남은 격차의 성격이 확정된다.**

```
2024 순위 품질 상한 (도달 불가)     716.51
현재 파이프라인                    683.77
LB 1000 에 필요한 로컬              약 930
```

**도달 불가능한 상한조차 717 이다.** 캘리브레이션 계열로는 원리적으로 930 에
못 간다. 1등과의 격차는 **순위 매기기 품질** 그 자체이며, 우리가 못 찾은 예측
신호가 있다는 뜻이다.

### 4-12. 마지막 두 축 — 3차 상호작용과 학습된 선수 파라미터

**3차 상호작용 — 기각** (`probe_cross.py --order 3`).

주변부 3개와 2차 3개를 ANOVA 항등식으로 모두 제거하고 순수 3차 성분만 훑었다.
근거는 있었다 — 2차가 전부 0 으로 보이는 자리는 탐욕적 트리가 **경로 자체를**
못 찾는다. 루트에서도, 두 번째 분할에서도 이득이 없기 때문이다.

평가 폴드를 셋으로 바꿔가며 8,436 조합을 훑었다.

| 평가 폴드 | 최대 | 1위 조합 |
|---|---|---|
| 2024 | +13.69 | `middle_rate x success_rate x game_type` |
| 2022 | +10.47 | `ball_rate x success_rate x game_type` |
| 2023 | +104.29 | `batter_team x game_month x game_type` |

**세 폴드의 상위 목록에 겹치는 조합이 하나도 없다.** 노이즈의 서명이다.
유일하게 반복되는 `game_type` 은 2차 스윕에서 이미 폴드별 부호가 갈리는 것으로
확인된 피처다. 2023 의 100+ 는 그 해 캘리브레이션이 무너져 잔차와 상관되는
아무 구조나 크게 보이는 것이다 (4-11).

> 양수가 725/7,998 (9%) 뿐인 것도 정보다. 순수 노이즈면 이식 이득이
> `2d·잔차 − d²` 라 기대값이 `−E[d²]` 로 **음수**다. 즉 7,273개가 노이즈임을
> 스스로 증명한다.

**학습된 선수별 파라미터(임베딩) — 기각** (`embed_test.py`).

`pitcher_id` 는 데뷔 순 정수이고 트리는 순서형 분할만 하므로, 선수 정체성 자체는
모델이 접근하지 못한다 (4-7). 엔티티 임베딩의 주장이 이 한계를 없앤다는 것인데,
**그 주장의 1차원 버전은 torch 없이 검증된다** — 로지스틱에 ID 를 one-hot 으로
넣으면 선수마다 학습된 계수가 하나씩 생긴다.

| 혼합 비중 | 0.05 | 0.10 | 0.15 | 0.20 |
|---|---|---|---|---|
| `lr` (현재) | 674.5 | **677.0** | 676.2 | 672.2 |
| `lr` + ID one-hot | 673.8 | 674.3 | 670.3 | 661.7 |

**모든 가중치에서 더 나쁘다** (정규화를 `C=0.1 → 0.01` 로 세게 해도 마찬가지).

이유가 설명된다. `asof_pitcher_success_rate` 가 이미 그 선수의 제구 능력을
담고 있고, 그걸 통제하고 남는 선수별 변동은 노이즈다. 게다가 **평가 시즌은
투구의 약 20% 가 신인**이라 학습된 파라미터가 아예 없는 행이 5분의 1 이다.

> **다차원 임베딩도 기대하기 어렵다.** 임베딩이 1차원보다 나을 수 있는 지점은
> "정체성 x 상황" 상호작용인데 그것도 이미 쟀다 — `indiv`(투수 x 타자좌우 개인
> 편차) +7.63 에 부호 엇갈림, `px_count` ~0 (4-7). 주효과와 상호작용 버전이
> 둘 다 약하다. torch 2.5GB 설치와 제출 배선 위험(오프라인 설치 10분 제한,
> 6-4 전례)을 감수할 근거가 없다.

### 4-13. 목적함수 정렬 — 붕괴 해 보험이지 평시 이득이 아니다

**격자의 축 하나가 통째로 빠져 있었다.** 4-1 에서 잎·반복수·규제를 전부 훑었지만
**손실함수는 한 번도 후보가 아니었다.** 지금 HGB 는 log-loss 로 학습하는데 평가는
Brier 다. `HistGradientBoostingRegressor(loss="squared_error")` 로 0/1 타깃을
회귀하면 평가지표를 직접 최소화한다 (`objective_test.py`).

```
brier − logloss (단독, 클리핑 없는 BSS, 2시드)
1시즌 +2.11   2시즌 −14.29   3시즌 −0.67   4시즌 +41.27   5시즌 +12.38

5폴드 평균                     +8.16
2023(붕괴 해) 제외 4폴드 평균   −0.12
```

**이득이 붕괴 해 하나에 몰려 있다.** 정상 해 네 개는 평균 −0.12, 표준편차 약 11
이고 2024 의 +12.38 은 그 분포에서 1.1 표준편차 위다 — 유의하지 않다.
학습량 추세도 없다 (3폴드만 보면 `−14 → −0.7 → +12` 로 단조로 보이지만 양끝을
채우면 무너진다. 4-11 의 잎 실험과 같은 함정).

**기각한다.** `alpha=0.8`(4-11)과 같은 구조다 — 붕괴 해 보험이고 평시 기대값이
0 인데, 2025 가 붕괴 해가 아니라는 직접 증거가 있다.

> **다만 비용이 음수인 변경이다.** 더 빠르고(66초 vs 92초), 붕괴 해에 +41,
> 평시 기대값 0. **국면 붕괴 신호가 잡히면 이게 첫 번째 카드다.**
> 배선 시 주의 — `HistGradientBoostingRegressor` 는 `predict_proba` 가 없어
> `script.py` 예측 경로를 손봐야 하고 pkl 형식이 바뀌므로 6-2 를 다시 돌려야 한다.

### 4-14. CatBoost — 간판 기능을 끄는 것이 핵심이었다

**이번 라운드 최대 발견.** CatBoost 가 단독으로 HGB 를 폴드마다 이긴다.

| 폴드 | 학습 | CatBoost | HGB(L10) | 차이 |
|---|---|---|---|---|
| 2020 | 1시즌 | 73.28 | 51.78 | +21.50 |
| 2021 | 2시즌 | 1320.63 | 1225.86 | **+94.77** |
| 2022 | 3시즌 | 2305.29 | 2261.04 | +44.25 |
| 2024 | 5시즌 | 698.55 | 660.95 | +37.60 |

**핵심은 ID 를 `cat_features` 로 선언하지 **않는** 것이다.**

```
ID 를 범주형으로 선언 (ordered target statistics 켬)   535.45 ~ 539.89
ID 를 숫자로 넘김 (그 기능 끔)                          698.55
                                                    차이 163
```

CatBoost 를 쓰는 통상적 이유가 고차원 범주형 처리인데 **이 데이터에서는 그게 독이다.**
그대로 썼으면 535 를 보고 "CatBoost 는 안 맞는다"고 기각했을 것이다 (실제로 두 번
그렇게 쟀다). 살린 근거는 4-12 다 — 학습된 선수별 파라미터가 `asof_*` 를 못 넘고,
평가 시즌은 투구의 20% 가 신인이라 그 인코딩이 근거 없는 값이 된다.

**남는 이점은 대칭 트리(oblivious tree)다.** 한 깊이의 모든 노드가 같은 분할을
공유하므로 깊이 6(잎 64)이어도 자유 성장 트리의 64잎과 표현력이 전혀 다르다.
4-1 이 규정한 **"표현력이 아니라 과신하지 않기"** 문제에, 잎을 조이는 것과는
**다른 경로로** 답한 셈이다. 실제로 예측 표준편차가 HGB 보다 좁고(0.0425 vs
0.0434) 중심 편차도 작다(+0.0107 vs +0.0119). 용량은 6배인데 더 조심스럽다.

> **이것이 "구조 축 6종 전부 음수"(4-10)의 의미를 정정한다.** 그 여섯은 전부
> `HistGradientBoosting` 이라는 **한 트리 계열 안에서의 변주**였다. 국소 최적이라는
> 진단은 맞았지만 "국소"의 범위가 좁았다. **앞으로 "이 축은 다 훑었다"고 적을 때
> 훑은 공간이 어디까지였는지 같이 적을 것.**

**확정 구성** — `hgb 0.30 / catboost 0.60 / lr 0.10`, `lam 0.03`.

격자에서 2024 폴드 정렬과 3폴드 평균 정렬이 모두 `cb 0.70~0.80` 을 가리켰지만
**0.60 을 골랐다.** 2024 기준 차이가 +1.23 뿐인데, CatBoost 의 이점이 학습량과
함께 줄어드는 방향(+94.8 → +44.3 → +37.6)이라 6시즌에서 더 줄 경우의 노출을
낮추는 쪽이 낫다. `lam` 은 상위권 전부에서 0.03 을 유지해 바꾸지 않았다.

홀드아웃: 앙상블 663.82 → 혼합 710.06(+46.24) → 중심 **716.39**(+6.33).
CatBoost 2시드 평균 단독이 709.49 로 HGB 앙상블(663.82)보다 +45.67 이다.

**RF(4-8)와 결정적으로 다른 점** — RF 는 `+128 → −39 → −92` 로 5시즌에서 이미
음수였고 6시즌 실전에서 −9.45 였다. CatBoost 는 폭이 줄어도 **부호가 유지된다.**

배선: pkl 4.25MB, 추론 34.8초, `catboost==1.2.10` 핀 추가.
**numpy 1.26.4 + catboost 환경에서 예측 파일 해시까지 동일**함을 확인했다
(6-2 4단계). 문자열 범주형 변환 목록은 번들에 순수 리스트로 담아 `script.py` 가
같은 변환을 한다 — 커스텀 클래스 없음 (6-3 준수).

### 4-6. 측정 방법 — 이걸 몰라서 잘못된 결론을 낼 뻔했다

**단일 폴드·단일 시드 측정은 믿을 수 없다.**

```
시드 노이즈    ±15  (같은 설정, fold 2024 에서 702.28 vs 687.68)
폴드 간 차이   ±45  (잎 효과가 2021 −44.5 / 2022 +31.5 / 2024 +18.4)
3폴드 평균     ±4   (시드 노이즈가 √n 으로 줄어든다)
```

fold 2024 에서 "잎 10→20 이 +23.3" 을 얻고 확정 직전까지 갔다. 24회 요인 실험
(잎 × ID × 3폴드 × 2시드)을 돌리니 실제 효과는 −0.72 였다. **그대로 제출했으면
제출 기회 하나를 −0.72 짜리 도박에 썼을 것이다.**

- 효과를 재려면 **최소 3폴드 × 2시드**. 폴드 안에서 비교하고(점수 스케일이 다르다)
  폴드별 부호가 갈리는지 반드시 확인할 것
- ~~2023 폴드는 어떤 구성으로도 0점이라 비교에 정보가 없다. 제외한다~~
  🚫 **이 판단이 틀렸다 (4-11).** 0 으로 만든 것은 `max(0, ...)` 클리핑이지
  폴드가 아니다. **클리핑 없는 BSS 로 재면 완벽히 비교 가능하고**, 되살려 보니
  축소계수의 답이 뒤집혔다(5폴드 0.80 vs 3폴드 1.00). 1/6 의 검증 신호를
  버려왔다. **구성 비교에는 클리핑 없는 지표를 쓸 것** (`extrap_test.py`)
- 곡선 최적점(`staged_predict_proba`)으로 재면 검증셋에 맞춘 낙관 편향이 있다.
  변형 간 비교에는 공정하지만 절대값은 부풀려져 있다
- **폴드별로 부호나 크기가 흔들리는 개선은 그 변동폭만큼 할인할 것.** 4회차에서
  로컬 +17 을 얻고 LB 는 +9.4 였다

**사전 선별 지표는 후보를 좁히는 데만 쓸 것. 채택은 반드시 학습으로 확인한다.**

학습 없이 "시즌을 넘어 살아남는 신호인가"를 재는 도구를 만들어 썼다
(`probe_interact.py`, `probe_cross.py`). 후보 17개 중 13개를 걸러낸 건 유용했다 —
`x inning` 은 같은 기간 안에서 +0.386 인데 시즌을 넘으면 +0.016 이라, 안 걸렀으면
그대로 넣고 유효한 것을 희석시켰을 것이다 (4-4 의 trackman 26개와 같은 구조).

그런데 **같은 지표가 두 번 틀렸고 두 번 다 학습 실험이 잡아냈다.**

| 지표가 말한 것 | 실제 | 왜 틀렸나 |
|---|---|---|
| `pitcher x batter_hand` 상관 +0.53 | 개인차분은 +7.63, 2024 음수 | 편차를 리그 전체 기준으로 빼서 **리그 성분이 섞여 있었다.** 리그분은 완벽히 지속되니 상관이 높을 수밖에 없다 |
| `park` 잔차 상관 +0.819 | **−23.09** | 투수 수준만 뺐는데 구장은 팀과 교란돼 있다. 남은 "지속성"은 모델이 이미 가진 팀 구성 구조였다 |

교훈은 **잔차를 어디까지 뺐는지가 지표의 의미를 결정한다**는 것이다. 모델이 이미
아는 축을 남겨두면 그게 그대로 상관으로 잡힌다. `probe_cross.py` 는 그래서
상관이 아니라 **점수 환산값**을 내도록 만들었지만, 그것도 기준선이 5분위 가법
모형이라 주변부가 강한 쌍에서는 부풀려진다 (`asof x asof` 쌍이 +314 로 상위를
차지하는데, 실제 HGB 는 그런 상호작용을 이미 잡는다).

## 5. 확정된 설정

```powershell
.\.venv\Scripts\python.exe final_train.py --leaves 10 --min-leaf 1000 `
    --n-iter 1100 --keep-ids --seeds 5 --save
```

같은 설정을 시드만 바꿔 5개 학습하고 예측을 평균한다.

```python
HistGradientBoostingClassifier(
    max_iter=1100,            # 전체 재학습 시 +10% → 1210
    learning_rate=0.02,
    max_leaf_nodes=10,
    min_samples_leaf=1000,
    l2_regularization=1.0,
    early_stopping=False,     # 시즌 홀드아웃으로 반복수를 이미 정했다
    random_state=42..46,
)
```

- 전처리: 범주형 3개(`top_bottom`, `game_type`, `base_state`)만 OrdinalEncoder
- **수치형은 passthrough.** `asof_*` 의 결측은 "아직 기록이 없다"는 정보이므로
  중앙값으로 덮지 않는다. HGB 는 결측을 분기 조건으로 직접 학습한다
- 학습 데이터: 2019~2024 전체, 균등 가중
- 피처 48개 — 원본 47개(**ID 포함**, 4-5) + 파생 `same_hand` (4-7)
- **계열 혼합** — `hgb 0.75 / rf 0.20 / lr 0.05` (4-8)
- **중심 보정** — `p + 0.03 x (그 행의 prev1 − 0.5238)` (4-9). `lam` 과 `c` 는
  pkl 에 담긴 상수이고 anchor 는 그 행 자신의 공식 입력이라 행 독립이다
- **파생은 `final_train.py` 와 `script.py` 의 `add_derived()` 두 곳에 같은 정의로
  있다. 한쪽만 고치면 학습과 추론이 어긋난다.** `bundle["features"]` 가 실제로
  쓸 컬럼을 정하므로, 파생을 모르는 옛 pkl 이 와도 무시되고 그대로 동작한다
- 축소 보정: 없음 (`alpha=1.0`)
- **국면 보정: 없음.** 규칙 위반이라 제거했다 (4-3)

**추론은 행 독립이다.** `script.py` 는 평가셋의 다른 행에서 얻은 통계를 일절
만들지 않는다. `alpha` 와 `center` 는 학습 시점에 정해져 pkl 에 담긴 상수다.

**시드 앙상블은 쓰고 다양성 앙상블은 쓰지 않는다.** 잎 구성이 다른 모델을 섞으면
예측이 중심 쪽으로 오므라들어, 그 이득의 상당 부분이 중심 보정과 겹친다 (4-5).
시드만 바꾸면 퍼짐은 그대로 두고 분산만 깎는다 — 2024 검증에서 단일 평균 691.4 →
5개 앙상블 697.36 (보정 포함 기준. 보정 없이는 645.54).

### 6-4. pkl 안의 numpy 난수 객체 — 여기서 두 번째로 실패했다

2회차 제출이 평가 서버에서 이 에러로 죽었다.

```
ValueError: <class 'numpy.random._pcg64.PCG64'> is not a known BitGenerator module.
```

`HistGradientBoostingClassifier` 는 학습 중 피처 서브샘플링에 쓰려고
`_feature_subsample_rng` (`np.random.Generator`, PCG64) 를 들고 있고, 이게 그대로
직렬화된다. numpy 는 이 객체의 피클 형식을 버전마다 바꿔 왔기 때문에, **평가 서버의
numpy 가 학습 환경보다 낮으면 로드 자체가 실패한다.** 모델이 좋고 나쁘고 이전 문제다.

근본 원인은 `requirements.txt` 에 numpy 가 없었던 것이다. sklearn 은 `numpy>=1.22`
만 요구하므로, 서버 이미지에 낮은 numpy 가 이미 있으면 **pip 이 그대로 두고 넘어간다.**
sklearn·pandas 만 핀을 박아서는 부족하다.

두 겹으로 막았다.

1. **`requirements.txt` 에 `numpy==2.2.6` 을 핀으로 박는다** — 학습 환경과 일치시킨다
2. **pkl 에 난수 객체를 아예 담지 않는다** — `final_train.py` 의 `strip_rng()` 가
   저장 직전에 `_feature_subsample_rng` 를 지운다. 추론 경로는 `_predictors` 만
   쓰므로 예측은 완전히 동일하다 (5만 행에서 최대 차이 0.00e+00 확인)

**재현과 검증 방법.** 낮은 numpy 환경을 따로 만들어 실제로 재현했고, 고친 pkl 이
통과하는 것까지 확인했다. 앞으로 pkl 형식을 건드리면 이 검사를 다시 할 것.

## 7. 남은 작업

**지금 상태** — 규칙 준수 + `same_hand` 판 `submit.zip` 이 검증까지 끝나고 대기
중이다 (6-2 점검 목록 4단계 전부 통과, 위반 코드 잔존 0건). 로컬 661.03.
지난 이력은 1장 제출 표, 실험 결과는 4장.

- [ ] **6회차 제출 여부 결정** — 로컬 661.03, 예상 LB 826~835. 현재 기록
      872.15 는 규칙 위반 상태다
- [ ] 주최측 문의 검토 — 새 제출이 이전 기록을 지우지는 않는다

> **환산 근거.** 규칙 준수 기준선은 로컬 645.54 / 예상 LB 약 817 이었다.
> `same_hand` 로 로컬 +15.49. 여기에 두 가지 환산을 적용하면 —
> 4회차 실측 비율 0.55 → **+8.5**, 1장의 직선 기울기 1.16 → **+18**.
> 폴드 부호가 일관되므로 4-6 의 할인은 거의 적용되지 않는다.

### 다음에 확인할 것 (우선순위 순)

**진단이 바뀌었다.** 4-5 는 "파생 피처 방향은 고갈됐다"고 결론지었지만, 그건
**주변부 통계에 한정된 것**이었다 — 기각 목록 12개가 전부 `asof_*` 의 재표현
이었던 게 그 증거다. 4-7 이 연 축은 다르다. **문제는 데이터가 아니라 모델
계열의 구조적 한계이고, 남은 개선은 그쪽에 있다.**

1. **3중 이상 상호작용** — `probe_cross.py` 는 2쌍만 본다. 2차는 고갈됐지만
   (4-7, 상한 +8) 3중은 아직 한 번도 안 봤다. 새 기준선이 있으니 확장 비용이
   낮다. `same_hand x strikes_before`, `same_hand x asof_pitcher_middle_rate`
   같은 조합이 상위에 보이는 것이 단서다
2. **중심 보정 확장 (4-9)** — 지금은 `prev1` 하나에 `lam=0.03` 이다.
   여러 anchor 를 동시에 쓰는 다변량 형태(각각 작은 lam)나, 투수 표본 수에
   따라 lam 을 바꾸는 형태는 미검증이다. 중심 편차가 아직 +0.0101 남아 있어
   여기에만 **40점**이 묶여 있다
3. **RF 혼합 재검토** — 2024 폴드에서 로지스틱(+8.24)보다 +1.65 크다(+9.89).
   차이가 폴드 노이즈 안이라 배선 위험 때문에 미뤘을 뿐 기각은 아니다.
   RF 직렬화가 6-4 를 통과하면 3자 혼합(+10.99)까지 갈 수 있다.
   덤으로 **RF 는 축소계수 이식이 +23.61 로 양수다** (HGB 는 −2.93). 평균화로
   일관되게 과소확신이라 그 성질이 폴드를 넘어 유지된다 — 4-5 의 축소 보정
   기각은 HGB 에 대해서만 유효했다
4. **선수별 조건부 인코딩 재검토** — 4-7 기준 +7.63 이고 2024 폴드 부호가
   뒤집힌다. 1번이 잘 되면 이건 필요 없어질 수 있다. `interact_feat.py` 에
   도구는 이미 있다
5. **Trackman 을 정적 프로필이 아닌 방식으로** — 대응표(`pitcher_id_map.csv`)는
   확보돼 있다. 실패 원인이 "`pitcher_id` 와 중복"이었으므로,
   - `pitcher_id` 를 빼고 프로필로 대체 → 미지 투수(2025 의 약 20%)에게도
     물리 정보가 붙는다. ID 가 못 하는 일이다
   - 시즌별 프로필의 **변화량**(작년 대비 구속 저하, 릴리스 변화). 정적 상수가
     아니라 시간에 따라 움직이는 값이라 중복되지 않는다
6. **2023 형 붕괴의 정체 파악** — 중심을 맞춰도 0점이라는 건 그 해에 피처-타깃
   관계가 끊어졌다는 뜻이다 (4-2). 점수보다 보험 성격이지만, 한 번 맞으면 전부를
   잃는 위험이다

> **기각된 방향** — 볼카운트 구간별 분할 모델링은 4-7 이 사실상 답했다.
> `count_state` 명시 교차가 −6.28, `mix_count` 의 카운트 차원이 0 이었다.
> 카운트는 주변부 효과가 강해 트리가 이미 충분히 쓰고 있다.

> 평가 시점에 그 투수의 직전 투구들을 입력으로 받아야 하는데, 그것들은 전부
