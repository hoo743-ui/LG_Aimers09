# LG Aimers 9기 — Tabular Machine Learning

> Trackman 투구 데이터를 활용해 **투구 단위 제구 성공 확률을 예측**한 머신러닝 프로젝트입니다.

## Overview

2019~2024년 KBO 투구 데이터를 기반으로, 투구가 이루어지기 **전에** 확인할 수 있는 정보만으로 `control_success` 확률을 예측했습니다.

핵심은 **데이터 leakage를 방지하면서 연도·시즌 변화에도 일반화되는 모델을 만드는 것**이었습니다. 평가셋이 학습 구간 밖의 시즌(2025)이기 때문에, 로컬 검증 점수보다 **시즌을 건너 전이되는지**가 실제 성능을 갈랐습니다.

평가 지표는 `1e5 x corr(예측, 정답)^2` 입니다. 상관 기반이라 **스케일·절편 보정으로는 점수가 오르지 않고**, 예측의 순위 구조 자체를 개선해야 합니다.

## Result

| | 리더보드 |
|---|---:|
| 베이스라인 (RandomForest) | 549.64 |
| CatBoost + 캘리브레이션 | 942.46 |
| **최종** | **1049.92** |

가장 큰 상승(+85.65)은 모델 교체가 아니라 **데이터 해석**에서 나왔습니다. 공식 `asof_*` 컬럼이 시즌마다 초기화되는 값이 아니라 **통산 누적**이라는 것을 실측으로 확인하고, 학습 데이터로 만든 선수별 상수를 빼서 **현재 시즌 상태를 대수적으로 복원**했습니다.

```
cur_n    = asof_n(행) - prior_n[선수]
cur_rate = (asof_n x asof_rate - prior_events[선수]) / cur_n
```

모델이 보는 통산 비율에는 과거 이력과 현재 폼이 섞여 있고, 모델은 그 선수의 직전 시즌말 통산을 모르므로 **원리적으로 두 성분을 가를 수 없습니다.** 이 분해가 그것을 갈라 줍니다. 복원 검증에서 `cur_n` 이 실제 시즌 내 순번과 100.0000% 일치했습니다.

## Engineering / Analysis Focus

### Leakage Prevention

예측 시점 이후에 알 수 있는 정보를 학습에 사용하지 않도록 변수의 생성 시점과 의미를 확인했습니다.

### Feature Engineering

투수·타자 특성, 볼카운트, 주자 상황, 과거 투구 이력 등 예측 시점에 이용 가능한 정보를 조합해 피처를 설계했습니다.

### Experiment-driven Development

한 번에 여러 요소를 변경하기보다 실험 결과를 기록하고 다음 가설을 설정하는 방식으로 모델을 개선했습니다. 기각된 실험도 이유와 함께 남겨 같은 시도를 반복하지 않도록 했습니다.

### Local-to-Leaderboard Transfer

로컬 검증에서 좋았던 구성이 실제 평가셋에서 **오히려 떨어지는 사례**를 여러 번 겪었습니다 (한 후보는 로컬 +1.36%인데 리더보드 −8.55). 이후에는 로컬 점수 자체보다 **어느 검증 구간의 부호가 실제 결과와 일치하는가**를 기준으로 후보를 걸렀습니다.

### Validation Design — 검증 폴드가 무엇을 재고 있었는가

후보 판정이 계속 빗나가서 **검증 폴드 자체를 감사**했습니다. `game_type` 하나만
알고 그룹 평균을 찍었을 때의 점수를 시즌별로 계산했더니 이렇게 나왔습니다.

| 시즌 | F−R 격차 | game_type 만으로 얻는 점수 | 실제 폴드 점수 | 비중 |
|---|---:|---:|---:|---:|
| 2021 | +0.191 | 1374.4 | 1634.9 | **84.1%** |
| 2022 | +0.205 | 1820.9 | 2458.4 | **74.1%** |
| 2024 | −0.030 | 38.7 | 916.3 | 4.2% |

**2021·2022 폴드 점수의 대부분은 모델 실력이 아니라 한 컬럼의 그룹 평균이었습니다.**
2022 의 2458 과 2024 의 916 은 난이도 차이가 아니라 사라진 공짜 신호의 차이입니다.

원인은 **타깃 정의의 변경**이었습니다. `game_type=F` 의 성공률이 2022 년 0.709
에서 2023 년 0.473 으로 무너지는데, 양쪽에 등판한 공통 투수 92명 중 **91명이
같은 방향으로 −0.226** 이동했고 그 해 투수 교체율은 6년 중 가장 낮았으며 상황
변수는 그대로였습니다. 실력도 구성도 아닌 기록 기준의 변경입니다.

이 발견으로 오랫동안 설명하지 못했던 특정 폴드의 퇴화(`rho²` 192 vs 2458)가
정리됐고, **어느 폴드를 판정 근거로 삼아야 하는지**가 확정됐습니다.

### Screening Before Training

학습 한 번이 15~30분이라 **돌리기 전에 거르는 규칙**을 만들었습니다. 후보 피처와
현행 모델 잔차의 상관을, 이미 모델에 들어 있는 피처의 그것과 나란히 놓는 방식입니다.

같은 대역이면 정보가 이미 회수된 것입니다. 실제로 두 후보를 학습 없이 기각했습니다.
다만 반대 방향으로는 성립하지 않는다는 것도 확인했습니다 — 통과시킨 후보가
실측에서 음수로 나왔습니다. **기각용 지표이지 채택용 지표가 아닙니다.**

## Key Takeaway

이 프로젝트를 통해 모델 구조 자체보다 **데이터의 생성 과정과 검증 설계가 일반화 성능에 더 큰 영향을 줄 수 있다는 점**을 경험했습니다.

실제로 모델 계열 교체(LightGBM, FM/DeepFM, MoE, TabPFN)는 모두 개선을 만들지 못했고, 점수를 올린 것은 **주어진 컬럼의 의미를 다시 읽은 것**과 **트리가 스스로 만들 수 없는 형태를 명시적으로 제공한 것** 두 가지였습니다.
