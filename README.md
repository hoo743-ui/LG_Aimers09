# LG Aimers 9기 — Tabular Machine Learning

> **Trackman 데이터를 이용해 투구 단위 제구 성공 확률을 예측한 머신러닝 프로젝트**

**Initial → Current Champion: 1071.8146**

## Overview

2019–2024년 KBO Trackman 데이터를 학습하고, 학습 구간 밖의 2025년 시즌을 평가 대상으로 사용했습니다.

예측 시점 이후에 알 수 있는 정보를 제외하면서, 시즌이 바뀌어도 유지되는 신호를 찾는 것이 핵심이었습니다.

평가 지표는 `1e5 × corr(prediction, target)^2`인 상관 기반 지표입니다. 따라서 단순한 스케일·절편 보정보다 **예측의 순위 구조 자체를 개선하는 것**이 중요했습니다.

약 245,789개 test sample을 제한 시간 안에 추론해야 했기 때문에 일반화 성능과 함께 추론 비용도 고려했습니다.

## Result

| Stage | Score |
|---|---:|
| RandomForest baseline | 549.64 |
| CatBoost + Calibration | 942.46 |
| Previous Champion | 1057.34 |

## 1. Data Interpretation — `asof_*`의 의미를 다시 확인

가장 큰 개선 중 하나는 모델 선택이 아니라 **컬럼의 의미를 다시 확인한 것**에서 나왔습니다.

`asof_*` 컬럼이 시즌별 누적값이라고 가정했지만 실제 데이터를 선수별·시즌별로 확인한 결과 **통산 누적값**임을 확인했습니다.

직전 시즌까지의 누적값을 분리하면 현재 시즌 상태를 복원할 수 있었습니다.

```text
cur_n    = asof_n - prior_n
cur_rate = (asof_n × asof_rate - prior_events) / cur_n
```

복원한 `cur_n`은 실제 시즌 내 순번과 **100% 일치**했습니다.

이렇게 과거 이력과 현재 시즌 상태가 섞여 있던 통산 지표를 분리했고, 생산 경로에서 **796.8 → 899.4**의 개선을 확인했습니다.

핵심은 모델이 통산 지표 하나만 보고 있을 때는 과거 이력과 현재 폼을 구분하기 어렵다는 점이었습니다. 현재 시즌 정보를 명시적으로 제공하면서 모델이 활용할 수 있는 정보 공간을 바꿨습니다.

---

## 2. Validation Audit — 검증 폴드가 실제로 무엇을 측정하는가

후보 판정이 반복해서 빗나가면서 모델보다 **validation split 자체를 감사**했습니다.

`game_type` 하나만 사용해 그룹 평균을 계산했을 때 일부 fold의 점수 대부분을 설명할 수 있었습니다.

| Season | game_type only | Actual fold | Contribution |
|---|---:|---:|---:|
| 2021 | 1374.4 | 1634.9 | **84.1%** |
| 2022 | 1820.9 | 2458.4 | **74.1%** |
| 2024 | 38.7 | 916.3 | 4.2% |

2021·2022 fold의 높은 점수가 모델의 일반화 성능만을 의미하지 않는다는 것을 확인했습니다.

원인은 `game_type=F` 성공률이 **2022년 0.709 → 2023년 0.473**으로 크게 변한 데 있었습니다.

두 시즌에 모두 등장한 공통 투수 92명 중 **91명이 같은 방향으로 이동**했고, 투수 구성이나 상황 변수만으로 설명하기 어려운 변화였습니다. 기록 기준 또는 타깃 정의가 변경됐을 가능성을 확인했습니다.

이 분석을 통해 어떤 fold를 단순히 높은 점수라는 이유로 채택하면 안 되는지 판단할 수 있었고, **local-to-leaderboard transfer를 평가하는 기준**을 다시 세웠습니다.

## 3. Screening Before Training

한 번 학습하는 데 15–30분이 걸렸기 때문에 후보 피처를 모두 학습시키기 전에 불필요한 후보를 줄이는 방법을 만들었습니다.

후보 피처와 현재 모델 잔차의 관계를 기존 입력 피처와 비교해, 이미 모델이 회수하고 있는 정보와 유사한 후보를 먼저 기각했습니다.

실제로 두 후보를 학습 없이 제거할 수 있었습니다.

다만 **기각용 지표가 채택용 지표는 아니라는 한계**도 확인했습니다. 스크리닝을 통과한 후보가 실제 학습에서는 음수 효과를 보이는 경우가 있었기 때문입니다.

---

## 4. Rebuilding the Baseline

기존 모델이 상황별 편차를 표현하고 있었지만 **투수와 타자의 전반적인 수준 자체를 나타내는 축이 부족하다**고 판단했습니다.

투수 주효과를 추가해 **1061.50**, 타자 주효과를 추가해 **1071.31**까지 개선했습니다.

여기서 중요한 것은 새로운 피처 하나를 추가한 것이 아니라, **기준선 자체가 바뀌면서 기존에 닫았던 가설을 다시 탐색할 이유가 생겼다는 점**입니다.

---

## 5. Current Champion — Pitcher × Ball Advantage

새 기준선에서 다시 탐색하면서 `balls > strikes` 상황의 **투수 × 볼우위** 축을 확인했습니다.

기존 대비 축과 겹침이 낮고 여러 검증 구간에서 같은 방향을 보인 후보를 실제 LB에서 확인했고,

**1071.8146**으로 Current Champion을 갱신했습니다.

---

## 6. Failed Experiments Matter

1071점대 이후에도 모든 후보가 개선을 만들지는 않았습니다.

한 후처리 후보는 로컬에서 좋아 보였지만 실제 LB에서는 **1071.81 → 1064.75**로 하락했습니다.

변화량을 다시 분해해 특정 후처리 축에서 대부분의 하락이 발생한 것을 확인했고, 구현 오류가 아니라 **local improvement가 leaderboard로 전이되지 않는 문제**임을 확인했습니다.

따라서 해당 축은 철회하고 기존 Champion을 유지했습니다.

최근에는 새로운 모델을 계속 추가하기보다 표현 공간, 모델 다양성, 정보 상한을 확인하며 **현재 모델이 이미 설명하고 있는 정보와 아직 남아 있는 정보의 경계**를 측정하고 있습니다.

---

## Experiment Principles

1. **데이터의 의미를 먼저 확인한다.**
2. **Validation score가 실제 전이를 의미하는지 확인한다.**
3. **가설을 세우고 한 번에 하나씩 검증한다.**
4. **실패한 실험도 원인을 분해해 기록한다.**
5. **새로운 점수보다 재현 가능한 근거를 우선한다.**
